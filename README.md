# 产品经理能力训练平台

一个跑在本机的产品能力训练工作台。核心是一条闭环：

**读书 / 看文章输入 → 沉淀成方法论 → 在 AI 训练师里刻意训练 → 拿到报告和下一步建议**

四个模块：

| 模块 | 作用 |
| --- | --- |
| **记录总结** | 图书 / 文章 / 笔记思考的结构化记录：总结、要点、我自己的思考、标签与关联领域 |
| **方法论** | 跨领域知识点卡片（心理学、经济学、商业与战略、产品设计、用户研究、数据分析、项目管理、增长运营），内置 21 张起步卡片 |
| **AI 训练师** | 3 个训练场景 × 4 种训练模式，支持联网检索与 MCP 工具，每次训练结束产出评估报告 |
| **设置** | AI 配置（任意 OpenAI 兼容端点）、联网与 MCP、提示词管理（场景块 / 模式块都可单独调） |

## 快速开始

```bash
npm install
npm run dev
```

打开 http://localhost:3000 ，先到 **设置 → AI 配置** 填入 Base URL、模型名和 API Key，
点「测试连接」确认可用，然后就可以开始训练了。

其它命令：

```bash
npm run build      # 生产构建（含 TypeScript 校验）
npm run start      # 跑生产版本
npm run typecheck  # 只做类型检查
```

技术栈：Next.js 16（App Router / Turbopack）、React 19、TypeScript，样式是手写的 CSS 设计系统，
没有引入 UI 组件库。

## AI 配置

任何 OpenAI 兼容端点都可以，平台会自动在 Base URL 后追加 `/chat/completions`。
设置页提供了几个预设：OpenAI、OpenCode Zen Go、DeepSeek 官方、本地 Ollama。

API Key 只保存在本机 `data/settings.json`，该目录已加入 `.gitignore`，不会被提交。

> **关于 OpenCode Zen / Go 网关**：该网关要求每次请求带会话标识头，缺失会直接返回
> `400 MissingSessionID`。平台已自动为每个训练会话发送 `x-opencode-session`，
> 所以可以开箱使用；对其它端点而言这个头会被忽略，没有副作用。

## 训练设计

### 三个场景

| 场景 | 期望产出 |
| --- | --- |
| **产品拆解** | 按 8 步流程走完，产出结构化的产品拆解文档（竞品分析归在这里） |
| **需求调研** | 需求假设清单 + 访谈提纲 + 验证方案 + 判定标准 |
| **流程设计** | 主流程 + 异常分支 + 角色职责 + 关键指标 + 落地风险 |

### 产品拆解的 8 步流程

带分步流程的场景会在会话页显示进度条，每一步都写明**交付物**和**去哪里获取信息**：

| 步骤 | 交付物 |
| --- | --- |
| 1 确认拆解目标 | 拆解目标确认卡 |
| 2 场景与用户画像 | 场景描述卡（时间 / 地点 / 状态 / 替代方案） |
| 3 诊断匮乏感（仅 C 端） | 匮乏感评分表 + 匹配的产品方向 |
| 4 五层架构拆解 | 五层架构分析表（用户 / 应用 / 模型 / 数据 / 算法算力） |
| 5 Agent 四要素 | 四要素卡片（目标 / 能力 / 知识 / 边界） |
| 6 竞品分析与差异化 | 竞品功能矩阵 + 差异化定位一句话 |
| 7 MoSCoW 划定 MVP | MVP 范围定义表 |
| 8 Aha Moment | Aha Moment 描述卡 |

每轮回答后，平台会解析模型输出的「第 X 步」并自动推进进度。

### 四种模式

| 模式 | AI 参与 | 行为 |
| --- | --- | --- |
| **AI 助教引导** | 实时 | 先给框架和示范，再一步步带着走，每轮推进一步 |
| **AI Grill** | 实时 | 高强度质询，专挑未验证假设、含糊表述、缺失边界 |
| **苏格拉底追问** | 实时 | 只提问不给答案，用连续追问逼出你自己的结论 |
| **完全独立训练** | 不参与 | 过程 0 AI 介入，独立完成并提交后统一批改 |

### 报告闭环

每次训练结束都会生成报告：总分、分项评分、做得好的地方、需要改进的地方、可执行建议、下一步练什么。

产品拆解用 10 个维度、每项 5 分、总分 50，并按总分给出等级（≥40 优秀 / 30–39 良好 / 20–29 及格 / <20 需要重新拆解）。
报告可以导出为 **Markdown**，也可以生成 **PPT 大纲**。

报告生成有三层容错：本地修复模型输出的 JSON → 让模型自修一次 → 正则抢救字段。
模型格式抖动不会让一次训练白跑。

## 联网搜索与 MCP

设置页的「联网与 MCP」可以给 AI 加上外部检索能力。

**联网搜索**支持 5 个来源：

| 来源 | 密钥 | 说明 |
| --- | --- | --- |
| **Bing 国际版** | 不需要 | 默认。抓公开结果页，国内网络可直连 |
| DuckDuckGo | 不需要 | 国内多数网络不可达 |
| Tavily | 需要 | 为 AI 检索设计，结果带正文摘要，质量最好 |
| Serper | 需要 | Google 搜索结果 API |
| Brave Search | 需要 | 独立索引，国内网络可能不可达 |

**MCP** 支持 Streamable HTTP 传输的服务器。训练时会把它们提供的工具一并交给模型，
由模型自己决定要不要调用。

执行流程是「先工具、后作答」：

```
工具轮（不流式）→ 模型请求调用 → 执行 → 结果回灌 → 再问
        ↓
最终回答（流式）→ 打字机效果
```

对话里会留下工具调用痕迹（查了什么、拿到几条、是否失败）。
如果端点不支持 `tools` 参数（不少网关会直接返回 400），平台会自动降级为
「先检索一次、把结果注入系统提示词」，训练不会中断。

## 数据与备份

所有数据都是 `data/` 下的 JSON 文件，可以直接打开查看、复制备份：

```
data/
├── captures.json      # 记录总结
├── methodology.json   # 方法论卡片（首次访问自动播种 21 张起步卡片）
├── prompts.json       # 提示词模板（首次访问自动播种 9 个内置模板）
├── sessions.json      # 训练会话与报告
└── settings.json      # AI 配置（含密钥）
```

想恢复出厂状态，删掉 `data/` 即可，下次访问会重新播种内置内容。
换存储位置可以用环境变量 `PM_TRAINER_DATA_DIR`。

> ⚠️ `data/settings.json` 里有明文 API Key。删 `data/` 之前记得先把 Key 记下来。

## 已知限制

- 未配置 AI 端点时无法开始训练，平台不内置任何密钥。
- MCP 客户端目前只支持 Streamable HTTP，不支持 stdio 传输。
- Bing 的搜索结果是解析结果页得到的，Bing 改版可能导致失效，届时可换用 Tavily / Serper。
